# Crypto Signal Bot — Flutter App

A mobile app and website for displaying signals.

## Installing Flutter

If Flutter isn't installed yet — https://docs.flutter.dev/get-started/install

Check that everything is ready:

```bash
flutter doctor
```

## Setup

The project folder doesn't have any platform files yet (web/, android/, ios/, etc.) — they are generated by Flutter automatically. Run once:

```bash
cd flutter_app
flutter create .        # creates web/, android/, ios/, ... — does NOT touch lib/ or pubspec.yaml
flutter pub get
```

This is a one-time step; you don't need to repeat it in the future.

**If the console spits out messages during `flutter run`** like `DebugService: Error serving requests ... Cannot send Null` — these are noisy Flutter DevTools logs, **they don't affect anything**. The app will still open in the browser.

## Running the backend

In a SEPARATE terminal, start the API:

```bash
cd ..   # to the root of the crypto_trading_bot project
uvicorn api:app --reload --host 0.0.0.0 --port 8765
```

Check that the backend responds: open http://localhost:8765/health — it should return `{"status":"ok", ...}`.

**Recommendation:** in parallel, run `python main.py` so the bot continuously scans the market and fills up the history.

## Running the app

### On a computer (website)

```bash
flutter run -d chrome
```

A browser will open with your app. This is your **website**.

Build static files for deploying the site:

```bash
flutter build web
```

The output files will be in `build/web/` — you can upload them to any static host (Netlify, Vercel, GitHub Pages).

### On Android

Connect your phone via USB with debugging enabled and:

```bash
flutter run -d android
```

Or first check the available devices:

```bash
flutter devices
```

**Important:** on a real phone, change `baseUrl` in `lib/services/api_service.dart` to your computer's IP address on the local network (e.g. `http://192.168.1.100:8765`). To find the IP: Windows `ipconfig`, Mac/Linux `ifconfig`.

### On an Android emulator

```bash
flutter run
```

By default `baseUrl` for the emulator = `http://10.0.2.2:8000` — this is a special IP through which the Android emulator sees the host machine's localhost. No changes needed.

### On iOS (macOS only)

```bash
flutter run -d ios
```

```
│   ├── widgets/
│   │   └── signal_card.dart  — signal card
│   └── screens/
│       ├── home_screen.dart       — active signals
│       ├── history_screen.dart    — history (WIN/LOSS/EXPIRED)
│       ├── stats_screen.dart      — statistics and charts
│       └── signal_detail_screen.dart — trade details
```

## What each screen does

**Active signals** — current open positions. Shows: symbol, direction (LONG/SHORT), entry, SL, TP, confidence. Pull-to-refresh to update.

**History** — closed trades. Filters: all/WIN/LOSS/EXPIRED. Each one shows P&L in R.

**Statistics** — period switcher (day/week/month). Shows:
- Number of trades
- Win rate
- Profit in R
- Approximate % of deposit (at 1% risk per trade)
- Cumulative P&L chart by day

**Details screen** — opens when you tap a card: all the information including the full rationale for the signal.

## Development tips

- All the logic is in Python — Flutter only displays it. If you need to change something in the signals, edit `ai/signal_engine.py`, not the Dart code.
- Want to add a new screen? Create a file in `lib/screens/` and add a tab in `main.dart` or a route.
- Work with the API only through `ApiService`. Don't make direct `http.get` calls from screens.
- Want push notifications? That's a whole other story — it would require Firebase Cloud Messaging and backend work.
